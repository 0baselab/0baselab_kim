# 주식데이터수집기

국내 주식(KRX 코스피·코스닥 보통주) 데이터를 수집하는 개인용 로컬 도구입니다. 전체 요구사항은 `docs/spec.md`를 봅니다.
zip 안에는 exe가 두 개 있습니다.

| 파일 | 용도 |
| --- | --- |
| `주식데이터수집기.exe` | 화면(GUI). 더블클릭해서 씁니다. 검은 창이 뜨지 않습니다. |
| `주식데이터수집기-명령.exe` | 명령줄용 (`daily`, `briefing` 등). 인자 없이 실행하면 터미널 메뉴가 뜹니다. |

`주식데이터수집기.exe`를 더블클릭하면 화면(GUI)이 뜹니다. 탭은 [수집] [브리핑 데이터 가공] [테마 관리] [설정] 4개입니다.
매일은 장 열린 날 20:30~22:00에 [수집] 탭의 [수집 실행]만 누르면 됩니다. 아래 명령줄 사용법은 같은 기능을 명령으로 실행할 때 씁니다(터미널 메뉴는 `menu`).

## 1. 설치

1. GitHub 저장소의 **Releases**에서 가장 최신 버전의 `주식데이터수집기_v{버전}.zip`을 받습니다.
2. zip을 `C:\`에 풉니다. `C:\주식데이터수집기\주식데이터수집기.exe`가 생깁니다.
   - 바탕화면이나 OneDrive 폴더 안에는 설치하지 마세요. 설치 폴더에 API 키 파일이 생깁니다.
3. `주식데이터수집기.exe`를 더블클릭합니다.
   - 처음 실행하면 Windows가 **"Windows의 PC 보호"** 경고를 띄울 수 있습니다. 서명되지 않은 프로그램이라서 나오는 경고입니다.
     **"추가 정보"** 를 누른 뒤 **"실행"** 을 누르면 됩니다.

## 2. 업데이트

새 버전 zip을 같은 위치(`C:\`)에 풀어 덮어씁니다. 아래 두 가지는 zip에 들어 있지 않아 그대로 유지됩니다.

- `secret\keys.env` (API 키)
- `config\settings.env` (일반 설정)

## 3. 처음 실행할 때

- API 키 4개(`KRX_AUTH_KEY`, `KIS_APP_KEY`, `KIS_APP_SECRET`, `DART_API_KEY`)를 하나씩 묻습니다. 입력한 글자는 화면에 보이지 않습니다.
  키는 설치 폴더의 `secret\keys.env`에만 저장됩니다. 화면에는 앞 4자리만 표시됩니다.
- 데이터는 바탕화면의 `주식데이터수집` 폴더에 저장됩니다. 바탕화면이 OneDrive로 동기화되고 있으면 경고가 나옵니다.
  이때는 `config\settings.env`의 `DATA_DIR=`에 동기화되지 않는 폴더(예: `D:\주식데이터수집`)를 적습니다.

## 4. 수집 (메뉴 1·2번)과 상태 점검 (메뉴 6번)

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe daily
C:\주식데이터수집기\주식데이터수집기-명령.exe range --from 20261102 --to 20261106
C:\주식데이터수집기\주식데이터수집기-명령.exe status
```

- **장이 열린 날 20:30~22:00에 실행**하는 것을 기준으로 만들었습니다. (KIS 수급 API는 15:40~23:59에만 조회됩니다.)
- 처음 실행하면 거래일 달력을 만들고 KRX 250거래일(약 1,500회, 약 13분), KIS 수급 120거래일(약 1만 회, 약 17분)을 받습니다. 각각 시작 전에 확인을 묻습니다. 중간에 꺼도 다음 실행 때 이어서 받습니다.
- KIS 단계는 15:40~23:59에만 진행합니다. 15:40~20:00에는 애프터마켓 중이라 계속할지 묻고, 자정을 넘기면 멈춥니다. KRX 단계는 시간과 관계없이 진행합니다.
- 당일 시세·수급·지수는 KIS 값으로 잠정 저장하고, 다음 실행 때 KRX 확정값과 KIS 재조회 값으로 교체합니다. 바뀐 값은 DB의 `value_changes`에 남습니다.
- 이미 받은 날짜는 다시 받지 않습니다. `--force`를 붙이면 다시 받습니다. `--yes`를 붙이면 확인 질문을 건너뜁니다.
- 데이터: `주식데이터수집\db\market.sqlite`, 원본 응답: `raw\krx\`, `raw\kis\`, 실행 로그: `logs\`, DB 스냅샷: `backup\`(최근 7개).
- 상태 점검은 데이터별 마지막 수집일, 빠진 거래일, 빈 결과가 3번 연속인 항목, 실패 항목, 대상 종목 수를 보여주고, 키를 다시 입력할 수 있습니다.

### 브리핑 패키지 (메뉴 3번)

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe briefing --yes
C:\주식데이터수집기\주식데이터수집기-명령.exe briefing --date 20261118 --json
C:\주식데이터수집기\주식데이터수집기-명령.exe unclassified --days 20
```

- 기준일 기본값은 마지막 수집일입니다. 결과는 `주식데이터수집\briefing\briefing_{기준일}_{생성시각}.xlsx` (`--json`이면 JSON도).
- DB만 읽고 API는 부르지 않습니다. 당일 값은 잠정(KIS)이며 `0_안내`·`6_데이터상태` 시트에 표시됩니다.
- 테마는 `주식데이터수집\themes\theme_master.csv`(theme,code,name,basis,added_date,note)를 읽습니다. 없으면 빈 양식을 만들고 테마 시트 없이 만듭니다. 문제가 있는 줄은 빼고 `6_데이터상태`에 적습니다.
- `unclassified`는 최근 n거래일 동안 `5_미분류`에 오른 횟수를 종목별로 센 CSV를 `briefing\`에 만듭니다.

### DART 수집과 구글 시트용 CSV (메뉴 4·5번)

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe dart
C:\주식데이터수집기\주식데이터수집기-명령.exe dart-export
```

- 주 1회 또는 월 1회 실행합니다. 시간 제한은 없습니다. 대상은 마지막 수집일의 분석 대상 종목입니다.
- 처음에는 3년치 정기보고서(약 3만 회)를 받으므로 하루 한도(`DART_DAILY_LIMIT`, 기본 18,000회)를 다 쓰면 멈춥니다. 다음 날 다시 실행하면 이어서 받습니다. 남은 건수는 실행 요약과 상태 점검에 나옵니다.
- 분기 단독 값은 명세서 14.4 규칙으로 환산합니다(손익 4분기 = 연간 − 3분기 누적, 현금흐름 = 이번 누적 − 직전 누적).
- `dart-export`는 `주식데이터수집\dart_export\`에 `dart_financials_...csv`(기업·분기당 1행, 원 단위, TTM 포함)와 `dart_filings_...csv`를 만듭니다. 구글 시트에서 파일 > 가져오기 > 업로드 > "현재 시트 바꾸기"로 올립니다.

## 5. 실측 검증 실행 (메뉴 7번)

exe를 더블클릭하고 `7`을 입력하거나, 명령 프롬프트에서 아래처럼 실행합니다.

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe verify
```

결과는 `바탕화면\주식데이터수집\system\verify\` 폴더에 생깁니다.

| 파일 | 내용 |
| --- | --- |
| `실측보고서_{날짜-시각}.md` | 항목별 확인 결과 (이 파일을 돌려받습니다) |
| `raw_{날짜-시각}\` | API 원본 응답 |
| `snapshots\` | 같은 날 여러 번 실행한 기록 (3·6번 항목 비교용) |
| `holiday_{날짜}.json` | 휴장일조회 결과 (하루 1회만 호출하고 같은 날은 이 파일을 다시 씀) |

### 여러 시각에 반복 실행

3번(KIS 수급 당일 값)과 6번(KRX 당일 데이터) 항목은 **장이 열린 날** 아래 시각 무렵에 각각 한 번씩 실행해야 확인됩니다.

| 시각 | 확인하려는 것 |
| --- | --- |
| 15:45 | 당일 값이 처음 나오는지 |
| 16:30 | 값이 바뀌는지 |
| 18:00 | 값이 더 바뀌는지 |
| 20:30 | 실제 수집 예정 시각의 값. 10·11번 항목의 당일 값 기록 |

- 15:40 이전에는 KIS 수급 항목(1·2·3번)을 자동으로 건너뜁니다. 이 시간에는 KIS가 `OPSQ2001 TIME LIMIT` 오류로 과거 데이터까지 막기 때문입니다(0.1.1 실측).
- 10번(KIS 당일 거래량·대금 vs KRX)과 11번(KIS 업종지수 vs KRX 지수)은 장이 열린 날 밤에 기록하고, **다음 날 한 번 더 실행**해야 비교 결과가 나옵니다.

같은 날의 기록은 쌓이므로, **그날 마지막으로 만든 보고서 하나**에 모든 시각의 비교가 들어 있습니다.

### 과거 데이터 조회 가능 기간 실측 (`verify history`)

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe verify history
```

- KIS 투자자매매동향(3종목), KRX 일별 시세·지수, DART 재무가 몇 년 전까지 나오는지 확인합니다. 15:40 이후에 실행하세요(그 전에는 KIS를 건너뜁니다).
- 총 200회 이하, 약 1~2분. 수집 DB에는 아무것도 쓰지 않으며, 수집 DB가 없는 PC에서도 실행됩니다.
- 보고서: 데이터 폴더가 있으면 `주식데이터수집\system\verify\history_{시각}.md`, 없으면 설치 폴더 `verify_history\history_{시각}.md`.

### 백테스트용 10년 데이터 백필 (`backfill`)

```bat
C:\주식데이터수집기\주식데이터수집기-명령.exe backfill krx
C:\주식데이터수집기\주식데이터수집기-명령.exe backfill kis
C:\주식데이터수집기\주식데이터수집기-명령.exe backfill dart
C:\주식데이터수집기\주식데이터수집기-명령.exe backfill status
```

- 저장 위치: `주식데이터수집\backtest\backtest.sqlite` (정기 수집 DB와 별도). 순서는 krx → kis(15:40~23:59) → dart(며칠). 자세한 내용은 명세서 16장.
- 끊겨도 다시 실행하면 이어받습니다. 정기 수집과 동시에는 돌지 않습니다.

## 6. 실측 보고서를 돌려주는 방법

1. 그날 마지막 `실측보고서_{날짜-시각}.md`를 엽니다(메모장으로 열 수 있습니다).
2. **올리기 전에 아래를 확인합니다.**
   - 보고서 맨 끝에 "자동 보안 검사 — 키·토큰 문자열이 발견되지 않았습니다"가 있는지. "경고"가 있으면 올리지 말고 알려주세요.
   - `secret\keys.env`의 키 값 4개 중 어느 것도 보고서 안에 없는지 (메모장의 찾기 `Ctrl+F`로 각 키의 앞 8자리를 검색).
   - 계좌번호(숫자 8자리+2자리 형태)가 들어 있지 않은지. 이 프로그램은 계좌번호를 쓰지 않으므로 나오면 안 됩니다.
   - `kis_token.json`, `keys.env`, `settings.env` 파일은 **절대 올리지 않습니다.**
3. GitHub 저장소 웹 화면에서 `docs/verify/` 폴더로 이동해 **Add file → Upload files**로 보고서를 올립니다.
   (폴더가 없으면 **Add file → Create new file**에서 이름 칸에 `docs/verify/README.md`처럼 적으면 폴더가 생깁니다.)
4. 원본 응답(`raw_...` 폴더)은 요청받았을 때만 올립니다. 올릴 때도 2번 확인을 똑같이 합니다.

## 7. 개발자용

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest          # 가짜 응답으로만 테스트 (실제 API 호출 없음)
.venv/bin/python -m collector verify
```

- 실제 API를 부르는 테스트는 `tests/live/`에 두고 `pytest -m live`로만 실행합니다.
- 릴리즈: PR마다 `collector/version.py`의 버전을 올립니다. main에 병합되면 `.github/workflows/build.yml`이 그 버전의 태그가 없을 때만 Windows exe를 빌드하고 태그·Release를 만들어 zip을 올립니다. 이미 있는 버전이면 아무것도 하지 않습니다.
- PR에서는 같은 워크플로가 Windows 테스트·빌드를 돌리고, 이미 릴리즈된 버전 번호면 실패로 알려줍니다.
