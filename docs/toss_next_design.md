# 토스 기반 다음 프로그램 설계 메모 (2026-11-24 기준, 확정 전)

토스측정(toss/) 측정 결과와 사용자 결정을 모은 메모입니다. 다음 프로그램(토스 수집기·자동매매기)을 만들 때
이 문서를 먼저 읽고, 바뀐 점은 사용자에게 확인합니다. 아래 "결정됨"은 사용자가 정한 것, "제안"은 아직 승인 전입니다.

## 결정됨

1. **토스 API만 사용한다.** KIS 분봉 수집과 연동하지 않는다. 토스 측정이 "대체 불가"로 나와도 토스 API 안에서 대안을 찾는다.
   - 이유: 자동매매를 토스로 하므로, 과거 검증 데이터와 장중 실시간 데이터의 출처가 같아야 한다.
2. **토스 프로그램은 회사 PC에서 돌린다.** 회사 PC에는 KIS 분봉 DB(danta.sqlite)가 없다.
   - KIS 비교(candles-compare) 대신 토스 자체 점검(candles-check)으로 판정한다.
3. **운영 흐름 (매일 반복)**
   1. 전일자 데이터까지 수집
   2. 전일자까지의 데이터 + 오늘 장중 필터링으로 자동매매
   3. 다음날 아침 프로그램을 켜서 전일자 데이터 추가 수집 + 장중 필터링으로 자동매매
   - 사람이 20시까지 PC 앞에 있는 전제를 두지 않는다. 전일자 작업은 다음날 아침에 한다.
4. **일봉 수집과 분봉 수집을 나눈다.**

   | 구분 | 용도 | 시점 |
   |---|---|---|
   | 일봉(및 순위 등 판단 재료) | 그날 아침 종목 필터링 | 장 시작 전 (오늘 매매 판단에 쓰는 값만) |
   | 분봉 | 나중에 거래 결과 검증용(보관) | 장 시작 전에 끝날 필요 없음. 장중(낮은 우선순위)·장 후·주말 |

## 측정으로 확인된 사실 (토스측정 0.1.0, 회사 PC, 2026-11-24)

- 종목 1분봉: 3년 상한(2023-11-24)까지 받아짐. 하루 약 716봉(08:00~20:00 통합). NXT 개장 전(2024년) 날짜에도 18~19시 봉이 있음 → 거래 없는 시간을 채운 봉일 가능성(candles-check로 확인 중).
- 종목 1분봉 timestamp = 봉 종료 시각. 지수 1분봉 timestamp = 봉 시작 시각.
- 일봉: 3년 상한까지 받아짐.
- 투자자별·프로그램 매매(종목별): 2019-04-01부터 약 1,879일. 거래량만 있고 금액은 없음. KRX+NXT 통합(프로그램 매매는 KRX만).
- 실시간 거래대금 순위: 약 1분마다 갱신. realtime의 거래대금은 하루 누적이 아님(집계 구간은 문서에 없음, 확인 필요).
- 투자자 순위: 외국인 장중 갱신, 기관은 늦게 갱신, 개인은 전일 기준. 과거 날짜 조회 불가.
- stocks/all은 거래 가능한 종목만 줌(상장폐지 0개) → 상장폐지 이력은 토스로 얻을 수 없음.
- 캔들(MARKET_DATA_CHART) 호출: 문서 한도 20/초의 절반(10/초)으로 보냈는데 429가 261회, 실제 약 4.6/초. 실제 한도는 limits 결과로 확정 필요.
- 캔들 호출 한도(limits): 응답 헤더 `X-RateLimit-Limit`은 문서대로 20인데, 10/초로 보내도 2,929회 중 267회(9%)가 429.
  지속 가능한 속도는 약 4.6/초 → **캔들은 5/초 이하로 보낸다.** 다른 그룹은 문서 한도의 절반에서 429 없음.

## 제안 (승인 전)

### 저장 용량 (추정, SQLite 행당 약 96바이트 기준, 보통주 약 2,544종목)

| 범위 | 1년 | 3년 |
|---|---|---|
| 정규장만(381봉) | 약 23GB | 약 68GB |
| 전체 세션(716봉) | 약 43GB | 약 128GB |

- 줄이는 방법: 거래량 0인 봉 저장 안 함, 정수 저장 + WITHOUT ROWID 표(행당 약 절반), 필요하면 Parquet.
- 첫 제안: 1년치, 정규장 + 거래량 있는 장전·장후 봉, 압축형 SQLite → 약 15~25GB 예상.
  (NXT 전 날짜와 NXT 미거래 종목은 장전·장후 봉이 모두 거래량 0이라 실제로는 정규장 규모에 가까울 것)

### 수집 시간 (캔들 실측 지속 속도 약 4.6/초 기준 → 5/초 이하로 운영)

- 분봉은 날짜와 무관하게 200봉씩 과거로 받으므로 저장 범위와 상관없이 08~20시 봉을 모두 받아야 한다.
- 처음 1년치: 약 220만 회, 약 5.5일 / 3년치: 약 660만 회, 약 16일 / 매일 전일자 보충: 약 1만 회, 약 37분.

### 구글 드라이브로 집·회사 나눠 수집할 때의 구조

- DB 하나를 동기화해서 두 PC가 번갈아 쓰지 않는다(쓰는 중 동기화 → 손상, 충돌 사본).
- 날짜별(또는 월별) 파일로 저장. 수집 중에는 동기화 안 되는 로컬 폴더에 쓰고, 다 받고 검사한 뒤 동기화 폴더로 옮긴다.
- 파일 안에 완료 기록(봉 수, 검사 결과)을 넣고, 그 기록이 있는 파일만 "받은 날짜"로 인정한다(파일명만으로 판단하지 않음).
- 작업 범위 분리: 회사 = 매일 전일자, 집 = 주말에 과거 날짜 채우기. 집 공인 IP도 토스 허용 IP에 등록. 두 PC 동시 실행 금지(토큰 1개).
- 확인 필요: 구글 드라이브 용량(무료 15GB), 회사의 개인 클라우드 동기화 정책.

### 호출 한도·토큰

- 장중 실시간 판단은 웹소켓(체결·호가, REST와 한도 별도) 중심으로 하고, REST 분봉 한도는 보관용 수집에 쓴다.
- 장중 보관용 수집은 매매보다 낮은 우선순위로, 속도를 낮춰 돌린다.
- 수집과 매매는 같은 프로그램 안에서 하거나 토큰 파일을 공유한다(토큰은 client_id당 1개, 재발급 시 이전 토큰 무효).
- 아침 준비 항목(필터링 재료)은 전략 분석 결과로 정해지므로 설정으로 바꿀 수 있게 만든다.

### 데이터 정합성 원칙 (측정으로 근거 확인됨)

- 토스 일봉은 KRX+NXT 통합 기준이다. 정규장 기준 일봉이 필요하면 1분봉을 직접 합쳐 만든다.
- 분석·장중 판단의 거래량은 분봉 합계 기준으로 통일한다(일봉 거래량에는 분봉에 없는 거래가 들어 있음).
- 장전·장후의 거래량 0인 봉(NXT 전 날짜는 전부, 이후에도 단일가 접수 시간 등)은 저장하지 않는다.
- 종가 단일가 체결 봉 위치가 종목 유형에 따라 다르다(보통주 15:30 시작, ETF 15:29 시작). 정규장 종가는 "15:30 이전에 시작한 마지막 거래 봉"으로 정한다.
- 정규장 분봉 일부 누락이 생기면 "채움" 표시를 하고, 누락이 많은 종목·날짜는 검증에서 제외한다.
